# AGENTS.md

Windows desktop widget for the MiniMax Coding Plan usage, with a self-contained WPF detail window and a Rainmeter companion skin.

## Setup commands

> This project is **Windows-only** and ships its own pinned .NET 8 SDK at `.tools/dotnet/`. Do not rely on a system-wide `dotnet`.

- **Build (single-file release)**:
  `pwsh -ExecutionPolicy Bypass -File scripts/Publish-App.ps1` (or `powershell`)
  → outputs `dist/win-x64/MiniMaxUsage.exe`
- **Test (C# / xUnit)**:
  `.tools/dotnet/dotnet.exe test tests/MiniMaxUsage.App.Tests/MiniMaxUsage.App.Tests.csproj --nologo`
- **Test (PowerShell, two suites)**:
  `powershell -ExecutionPolicy Bypass -File tests/powershell/Update-MinimaxUsage.Tests.ps1`
  `powershell -ExecutionPolicy Bypass -File tests/powershell/RainmeterSkin.Tests.ps1`
- **Install scheduled-task + Rainmeter skin**:
  `wscript scripts/Install-Task-Admin.vbs` (UAC prompt; registers the 1-minute refresh task)
- **Smoke-load the detail window directly**:
  `.tools/dotnet/dotnet.exe run --project src/MiniMaxUsage.App -c Debug`

## Project layout

- `src/MiniMaxUsage.App/` — WPF .NET 8 application (`MainWindow.xaml` + `MainViewModel` + custom `CircularGauge` / `TrendChart` controls)
- `tests/MiniMaxUsage.App.Tests/` — xUnit unit tests for the C# layer
- `tests/powershell/` — PowerShell + Rainmeter tests (`TestHarness.ps1` mini framework, two suites)
- `scripts/` — operational PowerShell + VBS: `Update-MinimaxUsage.ps1` (data fetcher), `Install-Task.ps1` / `Install-Task-Admin.vbs` (scheduler), `Set-MinimaxApiKey.ps1` (DPAPI key write), `Publish-App.ps1` (release build)
- `Skins/MiniMaxUsage/` — Rainmeter skin (`MiniMaxUsage.ini` + `@Resources/Freshness.lua` + `Variables.inc` generated by the installer)
- `docs/superpowers/` — design plans and specs (read-only reference; not required to build)
- `dist/` — publish output, gitignored
- `.cache/` — runtime cache (`cache.json`, `history.jsonl`, `last-success-epoch.txt`, `widget.log`, status text files), gitignored
- `.config/` — DPAPI-encrypted API key (`apikey.enc`), gitignored

## Code style

- C#: `Nullable=enable`, `ImplicitUsings=enable`, `net8.0-windows`, `WinExe`, `PublishSingleFile=true`, `SelfContained=true`, `RuntimeIdentifier=win-x64`. No editorconfig, no analyzer packages.
- XAML: 4-space indent, `WindowStyle=None` + `AllowsTransparency=True` custom title bar. Static `SolidColorBrush` resources are `po:Freeze="True"` for render perf.
- PowerShell: `Set-StrictMode` not enabled, but `try/finally` is used to release named mutexes and dispose resources. Numbers are formatted with `[System.Globalization.CultureInfo]::InvariantCulture` so Rainmeter parses them correctly on non-en locales.
- Line endings: CRLF on Windows (git default). When writing files via tooling, match the existing convention in each file.
- No formatter is wired up; run `dotnet format` if you want to enforce C# style before committing.

## Testing instructions

- All three test suites must be green before pushing:
  - C# xUnit (44 tests)
  - `Update-MinimaxUsage.Tests.ps1` (PowerShell collector logic, 5 tests)
  - `RainmeterSkin.Tests.ps1` (skin wiring + Lua freshness check, 8 tests)
- Add a unit test in `tests/MiniMaxUsage.App.Tests/` for every new C# behavior. Use the existing `TempDirectory` helper for filesystem fixtures.
- For PowerShell changes, extend the matching `*.Tests.ps1` and follow the `It / Assert-True / Assert-Equal` style from `TestHarness.ps1`.
- For skin/INI changes, the `RainmeterSkin.Tests.ps1` suite greps the ini for required `[Measure*]` sections — keep that contract intact.

## PR & commit conventions

- Branch from `main`; never push to it directly.
- Conventional Commits (`fix:`, `feat:`, `docs:`, `chore:`, `refactor:`). One logical change per commit.
- Push with the `gh` CLI (HTTPS remote is already configured; the legacy SSH URL is no longer used).
- Before opening a PR, run all three test suites locally and attach the green output.

## Security

- The API key is encrypted with Windows DPAPI (CurrentUser scope) and stored in `.config/apikey.enc` (gitignored). It is decrypted only inside the PowerShell process; the WPF EXE never touches the plain-text key.
- `apikey.enc` and the running `widget.log` are gitignored; do not commit them.
- The scheduled task runs at `LeastPrivilege` (not `HighestAvailable`) and `Interactive` logon, scoped to the current user. Do not change to `RunAsUser` / `Password` storage.
- The `Global\MiniMaxUsage.Refresh` named mutex serializes script invocations across the task scheduler and the manual WPF refresh button; keep it global so both processes can see it.
